# line-webhook（Supabase Edge Function）

LINEのグループ/個人メッセージを受け取り、棚卸しの記録・入荷予定の登録・在庫問い合わせに答えるボット。

## 役割
- **グループ**メッセージ … 棚卸しとして解釈し、餌ごとに記録（農場判定・複数餌のまとめ送信・ズレ確認に対応）
- **1対1(DM)**メッセージ … まず「入荷予定の登録／在庫の問い合わせ」として解釈し、**それに該当しなければ棚卸しとして処理**する（DMでも棚卸し可能）
  - 見分け方: **将来の日付があるもの＝入荷予定**（例「6/16 サイレージ 本場」）、**日付なしの数量報告＝棚卸し**（例「本場 チモシー 26個」「本場の棚卸し」）
  - DMで「棚卸」「取消」「キャンセル」の語を含むメッセージは、入荷予定と誤認しないよう必ず棚卸し処理に回す（日付指定の棚卸し・取消をDMでもできるように）
- **日付指定の棚卸し** … 「9/20 本場 チモシー 26個」「昨日の棚卸し 本場 チモシー 26個」のように日付を付けると、**その日付の記録**として登録する。日付は今日基準で「一番近い過去または今日」に解釈（未来にはしない）。日付なしは今日の記録。
- **棚卸しの取り消し**
  - **確認待ちの取消** … 「はい」で確定する確認が出ているときに「いいえ」「キャンセル」→ 記録せずに取り消し
  - **記録済みの削除** … 「本場 チモシー 棚卸し取消」→ その餌の（既定=今日、または指定日の）記録を削除。日付未指定でその日の記録が無ければ最新の記録を削除
  - **まとめて全消し** … 「本場 今日の棚卸しを全部取消」「9/20 本場の棚卸し全部消して」→ その農場・その日の全餌の記録を削除
- **棚卸し当日の入荷の加算確認** … 棚卸しした日と同じ日付の入荷予定がある餌は、記録後に「その入荷を在庫に加算しますか？」と聞き返す。棚卸し時にまだ届いていなかったものだけ「餌名」「両方」「全部」で加算指定（既定＝加算しない＝棚卸しに含まれていた前提）。加算した入荷には `arrivedAfterCount` フラグが付き、在庫計算で棚卸し当日でも上乗せされる（アプリの入荷カレンダー→予定の「変更」からもON/OFF可）。
- **送信取消(unsend)** … 直前に登録した入荷予定を取り消し

## 必要な Supabase Secrets
| 名前 | 用途 |
|---|---|
| `LINE_TOKEN` | LINE Messaging API チャネルアクセストークン |
| `LINE_CHANNEL_SECRET` | 署名検証用チャネルシークレット |
| `CLAUDE_API_KEY` | メッセージ解析に使うClaude APIキー |
| `SB_URL` | Supabase プロジェクトURL |
| `SB_SERVICE_KEY` | Supabase サービスロールキー |
| `ALLOW_GROUP_ID` | （任意）反応を許可するグループID |

## デプロイ（手動）
アクセストークンに有効期限があるため、GitHub Actions での自動デプロイは使わず、
**手元のCLIから都度デプロイ**する運用にしている。

```bash
# 1) ログイン（初回・トークン期限切れのときだけ。ブラウザで認証）
supabase login

# 2) デプロイ
supabase functions deploy line-webhook --no-verify-jwt --project-ref <PROJECT_REF>
```

- `<PROJECT_REF>` … Supabase > Project Settings > General > Reference ID
- `--no-verify-jwt` … LINE からの Webhook は Supabase JWT を持たないため必須
- `supabase login` はブラウザ認証で一時的な資格情報を使うので、長期トークンをリポジトリに保存しなくてよい

## 2026-07 の修正（無反応バグ対策）
- Claude解析の `max_tokens` を 4096 に引き上げ（長い棚卸しでJSONが途中で切れて解析に失敗するのを防止）。
- 返信(reply)が失効・失敗しても push で必ず届くようフォールバック（`say()`）。解析失敗や想定外でも必ず一言返す（無言をなくす）。
- 棚卸しの重複判定を「同じ月」→「同じ日付」に統一（別日の棚卸し記録を上書きせず残す。アプリ本体の挙動と一致）。

## 関連する Supabase テーブル
- `app_state`（id=main の data 列に在庫の全状態）
- `line_session`（source_idごとの農場モード・確認保留）
- `line_member`（user_idごとの担当農場）
- `line_order_map`（message_id→登録した発注、unsend取り消し用）
